Cómo ACTIVAR el entorno virtual desde Git Bash
------------------------------------------------------------

1. Abrir Git Bash.

2. Ir al proyecto:

cd ~/desktop/MiniAI

3. Activar el entorno:

source .venv/Scripts/activate

4. Confirmar que se activó.

Debe aparecer algo similar al inicio de la terminal:

(.venv)

Ejemplo:

(.venv)
mephi@Baticomputadora MINGW64 ~/desktop/MiniAI (develop)
$

------------------------------------------------------------
Cómo comprobar que Python corresponde al entorno
------------------------------------------------------------

Ejecutar:

which python

Debe apuntar a algo similar a:

/c/Users/mephi/desktop/MiniAI/.venv/Scripts/python

Después:

python --version
pip --version

pip debe mostrar una ruta dentro de:

MiniAI\.venv\Lib\site-packages

------------------------------------------------------------
Cómo DESACTIVAR el entorno
------------------------------------------------------------

Ejecutar:

deactivate

El prefijo:

(.venv)

desaparecerá.

5. GPU / LENOVO LEGION
============================================================

Problema detectado inicialmente:
PyTorch estaba instalado correctamente con CUDA, pero:

torch.cuda.is_available()

devolvía:

False

Además:

nvidia-smi

no podía comunicarse correctamente con el driver NVIDIA.

------------------------------------------------------------
Cambio realizado en Lenovo Legion
------------------------------------------------------------

Se abrió Lenovo Legion / Lenovo Legion Space.

En:

Configuración conveniente
→ Modalidad de funcionamiento de la GPU

El equipo estaba usando:

Modalidad híbrida

Se cambió temporalmente a:

Modalidad dGPU

Después se reinició la PC.

Resultado:
nvidia-smi volvió a detectar correctamente:

NVIDIA GeForce RTX 5050 Laptop GPU

Y PyTorch pudo usar la GPU.

------------------------------------------------------------
Qué hacer si CUDA deja de funcionar en el futuro
------------------------------------------------------------

Primero revisar Lenovo Legion.

Confirmar que la GPU NVIDIA esté disponible.

Si aparece un problema similar, probar:

Modalidad dGPU

y reiniciar.

Después ejecutar:

nvidia-smi

Si la RTX 5050 aparece correctamente, probar PyTorch.

============================================================

PyTorch fue instalado con soporte para CUDA 13.2.

Comando utilizado:

============================================================
11. ERRORES QUE YA ENCONTRAMOS
============================================================

Caso 1:
which python~

Problema:
Se agregó accidentalmente ~ al comando.

Correcto:

which python

------------------------------------------------------------

Caso 2:
Python interactivo mostraba:

...

Problema:
El intérprete estaba esperando finalizar un bloque multilinea.

Solución:
Usar una línea vacía para cerrar el bloque o ejecutar pruebas rápidas con:

python -c "..."

------------------------------------------------------------

Caso 3:
torch.cuda.is_available() = False

Aunque PyTorch mostraba:

2.14.0+cu132

Y:

torch.version.cuda = 13.2

Causa encontrada:
La GPU NVIDIA no estaba siendo correctamente expuesta al sistema bajo la configuración previa.

Solución aplicada:
Lenovo Legion
→ Modalidad GPU
→ Modalidad dGPU
→ Reiniciar

============================================================
12. RECOMENDACIONES
============================================================

- No instalar CUDA Toolkit adicional salvo que una fase futura realmente lo requiera.
- No reinstalar PyTorch si CUDA falla antes de revisar la GPU.
- Mantener el entorno virtual separado.
- Instalar nuevas dependencias siempre con .venv activo.
- Guardar dependencias importantes.
- Evitar llenar el proyecto con frameworks antes de necesitarlos.
- Comprobar CUDA antes de entrenamientos largos.
- Mantener la laptop conectada a corriente durante entrenamiento.
- Vigilar temperatura y VRAM en fases de entrenamiento.
